# KRN-008 - Preparación del entorno Chroot

## 1. Objetivo

Implementar un script para verificar los requisitos de una raíz LFS,
preparar los sistemas de archivos necesarios e ingresar al entorno mediante
Chroot cuando la instalación esté disponible.

## 2. Script implementado

Archivo: `scripts/krn-008/preparar-chroot.sh`

El script dispone de tres modos:

- `--check`: verifica los archivos y directorios requeridos sin realizar
  modificaciones.
- `--mount`: verifica los requisitos y prepara los sistemas de archivos
  necesarios para el Chroot.
- `--chroot`: realiza las verificaciones, prepara los montajes e ingresa
  al entorno LFS.

Si no se indica un modo, se utiliza `--check`.

## 3. Requisitos verificados

El script comprueba la existencia de:

- `/usr/bin/env`
- `/bin/bash`
- `/usr/bin`
- `/usr/sbin`
- `/usr/lib`

También comprueba que la raíz LFS sea un punto de montaje.

Para los modos `--mount` y `--chroot`, exige que la raíz permita escritura
y comprueba las herramientas necesarias del sistema anfitrión.

## 4. Montajes contemplados

El procedimiento prepara los siguientes sistemas de archivos:

- `/dev`, mediante montaje bind.
- `/dev/pts`, mediante devpts.
- `/proc`, mediante proc.
- `/sys`, mediante sysfs.
- `/run`, mediante tmpfs.

El script comprueba si los puntos ya están montados y evita repetir
los montajes existentes. Registra únicamente los montajes realizados
durante la ejecución actual para efectuar su limpieza automática al
salir del Chroot o cuando ocurre un error durante la preparación.

La limpieza se realiza en orden inverso al montaje.

## 5. Pruebas realizadas

### 5.1. Sintaxis

Comandos:

`bash -n scripts/krn-008/preparar-chroot.sh`

`git diff --check`

Resultado: sin errores de sintaxis ni problemas de formato en los
cambios revisados.

### 5.2. Verificación de una raíz LFS de referencia

Se utilizó la imagen de Lizzy en `/mnt/revision_lizzy`, montada en solo
lectura.

Resultado:

- `/usr/bin/env`: encontrado.
- `/bin/bash`: encontrado.
- `/usr/bin`: encontrado.
- `/usr/sbin`: encontrado.
- `/usr/lib`: encontrado.

La verificación terminó correctamente y no modificó el disco de referencia.

### 5.3. Verificación de la partición propia

Se ejecutó el modo `--check` sobre `/mnt/lfs`.

Resultado: se detectaron cinco requisitos faltantes porque la partición
todavía no contiene una instalación LFS completa.

El script detuvo correctamente el procedimiento.

### 5.4. Prueba de montajes y entorno de referencia

Para probar el ingreso al Chroot sin modificar la imagen de Lizzy,
se utilizó OverlayFS:

- La imagen de Lizzy se utilizó como directorio inferior de solo lectura.
- La partición propia se utilizó para almacenar los cambios de OverlayFS.
- Se utilizó `/mnt/lfs-root` como raíz combinada de prueba.

Se incorporó mediante montaje bind el directorio `lib64` de la imagen
de referencia, ya que era un montaje independiente y no aparecía
automáticamente dentro de OverlayFS.

El montaje de `lib64` se mantuvo en solo lectura.

### 5.5. Prueba del modo --mount

Se ejecutó el modo `--mount` sobre `/mnt/lfs-root`.

Resultado: se prepararon correctamente los montajes de `/dev`,
`/dev/pts`, `/proc`, `/sys` y `/run`.

### 5.6. Prueba del modo --chroot

Se ejecutó:

`sudo LFS=/mnt/lfs-root scripts/krn-008/preparar-chroot.sh --chroot`

Resultado:

- Se verificaron los requisitos básicos.
- Se prepararon los cinco montajes.
- Se ingresó correctamente al entorno Chroot.
- Se ejecutó Bash 5.3.9 dentro del entorno.
- Se salió mediante el comando `exit`.
- El script desmontó automáticamente `/run`, `/sys`, `/proc`,
  `/dev/pts` y `/dev`.

La comprobación posterior con `findmnt -R /mnt/lfs-root` confirmó
que los montajes temporales habían sido retirados.

También se desmontó manualmente el montaje adicional de `lib64`
utilizado para la prueba. Después de esto, únicamente permaneció
activo el montaje principal de OverlayFS.

## 6. Consideraciones y limitaciones

La partición propia `/mnt/lfs`, correspondiente a `/dev/sdc1`,
todavía no contiene una instalación LFS completa.

Por ello, la prueba real de Chroot se realizó utilizando una raíz
combinada mediante OverlayFS y la imagen de referencia de Lizzy.

El disco de Lizzy permaneció en solo lectura durante las pruebas.
No se modificó su instalación.

La prueba valida el funcionamiento del script y la limpieza de los
montajes, pero no representa una instalación LFS independiente
terminada en la partición propia.

# KRN-008 - Preparación del entorno Chroot

## 1. Objetivo

Implementar un script para verificar los requisitos de una raíz LFS,
preparar los sistemas de archivos necesarios e ingresar al entorno mediante
Chroot cuando la instalación esté disponible.

## 2. Script implementado

Archivo: `scripts/krn-008/preparar-chroot.sh`

El script dispone de tres modos:

- `--check`: verifica los archivos y directorios requeridos sin realizar
  modificaciones.
- `--mount`: verifica los requisitos y prepara los sistemas de archivos
  necesarios para el Chroot. Mantiene los montajes activos al finalizar.
- `--chroot`: verifica los requisitos, prepara o recupera los montajes
  necesarios e ingresa al entorno LFS.

Si no se indica un modo, se utiliza `--check`.

## 3. Requisitos verificados

El script comprueba la existencia de:

/usr/bin/env

/bin/bash

/usr/bin

/usr/sbin

/usr/lib

También comprueba que la raíz LFS sea un punto de montaje.

Para los modos --mount y --chroot, exige que la raíz permita escritura y comprueba las herramientas necesarias del sistema anfitrión.

La variable LFS debe contener una ruta absoluta. No se permite utilizar / como raíz LFS. También se resuelve la ruta real mediante realpath para evitar que un enlace simbólico apunte directamente a la raíz del sistema anfitrión.



## 4. Montajes y limpieza

El procedimiento prepara los siguientes sistemas de archivos:

/dev, mediante montaje bind del directorio /dev del sistema anfitrión.

/dev/pts, mediante el sistema de archivos devpts.

/proc, mediante el sistema de archivos proc.

/sys, mediante el sistema de archivos sysfs.

/run, mediante montaje bind del directorio /run del sistema anfitrión.

El script comprueba si los puntos ya están montados y evita repetir los montajes existentes.

### 4.1. Validación de la ruta LFS

Antes de realizar cualquier montaje, el script valida la ruta indicada mediante la variable de entorno LFS.

Se aplican las siguientes restricciones:

La ruta debe ser absoluta.

No se permite utilizar / como raíz LFS.

Se comprueba que el directorio exista.

Se resuelve la ruta real mediante realpath.

Se rechazan las rutas que, después de resolver sus enlaces simbólicos, apuntan a la raíz del sistema anfitrión.

Se comprueba que la raíz LFS sea un punto de montaje.

Estas validaciones evitan realizar operaciones de montaje sobre los directorios principales del sistema anfitrión.

### 4.2. Registro de los montajes

Para permitir que los montajes preparados con --mount puedan limpiarse posteriormente desde otra ejecución, se registra el ID de montaje y su ruta en un archivo de estado ubicado en /run.

El archivo tiene permisos restringidos al usuario administrador.

Cada montaje nuevo se registra inicialmente con el identificador PENDING. Después de realizar el montaje, se obtiene su ID mediante findmnt y se actualiza el registro con el identificador correspondiente.

Si ocurre un error al guardar el estado o al identificar el montaje, el script conserva el registro pendiente en memoria para que el mecanismo de limpieza pueda intentar desmontar el montaje realizado durante la ejecución actual.

### 4.3. Recuperación y verificación del estado

Al iniciar los modos --mount y --chroot, el script recupera los registros
 existentes del archivo de estado.

Antes de desmontar un sistema de archivos, compara el ID registrado con
 el ID del montaje que se encuentra activo.

Si ambos identificadores coinciden, se permite realizar el desmontaje.

Si el ID no coincide, el script no desmonta el punto,
 ya que podría tratarse de un montaje diferente al que había sido registrado.

Los registros PENDING de ejecuciones anteriores se conservan para revisión
 cuando no existe un ID verificable. No se desmontan automáticamente sin poder
 confirmar que pertenecen a la ejecución actual.

### 4.4. Manejo de errores y limpieza

El script utiliza un manejador de salida mediante trap EXIT para intentar limpiar
 los montajes cuando termina la ejecución por un error o cuando se sale del
 entorno Chroot.

La limpieza se realiza en orden inverso al montaje:

/run

/sys

/proc

/dev/pts

/dev

Cuando falla el registro de un montaje, el script intenta ejecutar la limpieza de
 los montajes realizados durante la ejecución actual.

Si la limpieza termina correctamente, se elimina el archivo de estado y su
 archivo temporal.

Si algún desmontaje falla o no puede verificarse la identidad del montaje,
 se conserva el archivo de estado para permitir su revisión posterior.

En el modo --mount, los montajes permanecen activos después de finalizar
 correctamente el script, permitiendo utilizarlos en una ejecución posterior del
 modo --chroot.

En el modo --chroot, los montajes se limpian automáticamente al salir del entorno.

Se realizaron pruebas para comprobar que el script rechaza rutas y modos no permitidos.

    sudo env LFS=/ scripts/krn-008/preparar-chroot.sh --check

Resultado:

    [ERROR] LFS debe ser una ruta absoluta: relativo

La ruta relativa fue rechazada correctamente.

**Prueba 3: Rechazo de modos no permitidos**

Comando ejecutado:

    sudo env LFS=/mnt/lfs scripts/krn-008/preparar-chroot.sh --invalido

Resultado:

    [ERROR] Modo no válido. Usa --check, --mount o --chroot.

El modo no permitido fue rechazado correctamente.

Las tres pruebas finalizaron con el mensaje de error esperado y
 sin realizar operaciones de montaje.

Estas comprobaciones permiten verificar que el script protege la raíz del sistema
 anfitrión, exige rutas absolutas y acepta únicamente los modos definidos
 para KRN-008.

### 5.5. Prueba del modo --mount sobre /mnt/lfs

Se ejecutó:

`sudo LFS=/mnt/lfs scripts/krn-008/preparar-chroot.sh --mount`

Resultado:

- Se prepararon `/dev`, `/dev/pts`, `/proc`, `/sys` y `/run`.
- Se registraron los IDs de los cinco montajes en el archivo de estado
  ubicado en `/run`.
- Se comprobó que el archivo de estado tenía permisos restringidos.
- Los montajes permanecieron activos después de finalizar el comando.

### 5.6. Prueba del modo --chroot sobre /mnt/lfs

Antes de ingresar al Chroot se comprobó que `/usr/bin/env` pudiera
ejecutarse dentro de la raíz LFS. Fue necesario corregir el enlace
del cargador dinámico en `lib64` para que el ejecutable pudiera iniciarse.

Después se ejecutó:

`sudo LFS=/mnt/lfs scripts/krn-008/preparar-chroot.sh --chroot`

Resultado:

- Se verificaron los requisitos básicos.
- El script reconoció los cinco montajes que ya estaban activos.
- Se recuperó el registro persistente de los montajes.
- Se ingresó correctamente al entorno Chroot.
- Se salió mediante el comando `exit`.
- El script desmontó automáticamente `/run`, `/sys`, `/proc`,
  `/dev/pts` y `/dev`.
- La comprobación posterior con `findmnt -R /mnt/lfs` confirmó que
  únicamente permanecía montada la partición principal.
- La comprobación de `/run` confirmó que el archivo de estado había
  sido eliminado después de la limpieza.

Esta prueba confirmó el funcionamiento conjunto de `--mount`,
`--chroot`, la recuperación del estado y la limpieza automática.

## 6. Consideraciones

La comprobación de archivos y directorios básicos no garantiza por sí sola
que todos los ejecutables de la raíz LFS puedan iniciarse. También deben
estar disponibles el cargador dinámico y las bibliotecas necesarias.

Durante la prueba sobre `/mnt/lfs` se identificó y corrigió el enlace
del cargador dinámico requerido por `/usr/bin/env`.

La limpieza compara los IDs de montaje registrados con los montajes
activos para evitar desmontar puntos cuyo montaje haya cambiado.

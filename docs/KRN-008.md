# KRN-008 - Preparación del entorno Chroot

## 1. Objetivo

Implementar un script para verificar los requisitos de una raíz LFS,
preparar los sistemas de archivos necesarios e ingresar al entorno mediante
Chroot cuando la instalación esté disponible.

## 2. Script implementado

Archivo: `scripts/krn-008/preparar-chroot.sh`

El script dispone de tres modos:

- `--check`: verifica los archivos y directorios requeridos sin realizar
  modificaciones.
- `--mount`: verifica los requisitos y prepara los sistemas de archivos
  necesarios para el Chroot. Mantiene los montajes activos al finalizar.
- `--chroot`: verifica los requisitos, prepara o recupera los montajes
  necesarios e ingresa al entorno LFS.

Si no se indica un modo, se utiliza `--check`.

## 3. Requisitos verificados

El script comprueba la existencia de:

- `/usr/bin/env`
- `/bin/bash`
- `/usr/bin`
- `/usr/sbin`
- `/usr/lib`

También comprueba que la raíz LFS sea un punto de montaje.

Para los modos `--mount` y `--chroot`, exige que la raíz permita escritura
y comprueba las herramientas necesarias del sistema anfitrión.

## 4. Montajes y limpieza

El procedimiento prepara los siguientes sistemas de archivos:

- `/dev`, mediante montaje bind.
- `/dev/pts`, mediante devpts.
- `/proc`, mediante proc.
- `/sys`, mediante sysfs.
- `/run`, mediante tmpfs.

El script comprueba si los puntos ya están montados y evita repetir
los montajes existentes.

Para permitir que los montajes preparados con `--mount` puedan limpiarse
posteriormente desde otra ejecución, registra el ID de montaje y su ruta
en un archivo temporal dentro de `/run`. El archivo tiene permisos
restringidos al usuario administrador.

Al ejecutar `--chroot`, el script recupera los registros y comprueba
que cada ID siga correspondiendo al montaje esperado antes de desmontarlo.
Así evita retirar accidentalmente un montaje que haya sido reemplazado.

La limpieza se realiza en orden inverso al montaje. Se ejecuta al salir
del Chroot y también cuando ocurre un error durante la preparación.

## 5. Pruebas realizadas

### 5.1. Sintaxis y formato

Comandos:

`bash -n scripts/krn-008/preparar-chroot.sh`

`git diff --check`

Resultado: sin errores de sintaxis ni problemas de formato en los
cambios revisados.

### 5.2. Verificación de una raíz LFS de referencia

Se utilizó la imagen de Lizzy en `/mnt/revision_lizzy`, montada en solo
lectura.

Se comprobaron los archivos y directorios requeridos por el modo
`--check`. La verificación encontró los elementos necesarios sin
modificar el disco de referencia.

### 5.3. Prueba anterior con OverlayFS

Para probar el ingreso al Chroot sin modificar la imagen de Lizzy,
se utilizó OverlayFS:

- La imagen de Lizzy se utilizó como directorio inferior de solo lectura.
- La partición de trabajo se utilizó para almacenar los cambios de OverlayFS.
- Se utilizó `/mnt/lfs-root` como raíz combinada de prueba.

Se incorporó mediante montaje bind el directorio `lib64` de la imagen
de referencia, ya que era un montaje independiente y no aparecía
automáticamente dentro de OverlayFS.

El montaje de `lib64` se mantuvo en solo lectura. La prueba permitió
comprobar el ingreso al Chroot y la limpieza de los montajes temporales.

### 5.4. Prueba del modo --check sobre /mnt/lfs

Se ejecutó:

`sudo LFS=/mnt/lfs scripts/krn-008/preparar-chroot.sh --check`

Resultado:

- `/usr/bin/env`: encontrado.
- `/bin/bash`: encontrado.
- `/usr/bin`: encontrado.
- `/usr/sbin`: encontrado.
- `/usr/lib`: encontrado.

La verificación terminó correctamente y no realizó cambios.

### 5.5. Prueba del modo --mount sobre /mnt/lfs

Se ejecutó:

`sudo LFS=/mnt/lfs scripts/krn-008/preparar-chroot.sh --mount`

Resultado:

- Se prepararon `/dev`, `/dev/pts`, `/proc`, `/sys` y `/run`.
- Se registraron los IDs de los cinco montajes en el archivo de estado
  ubicado en `/run`.
- Se comprobó que el archivo de estado tenía permisos restringidos.
- Los montajes permanecieron activos después de finalizar el comando.

### 5.6. Prueba del modo --chroot sobre /mnt/lfs

Antes de ingresar al Chroot se comprobó que `/usr/bin/env` pudiera
ejecutarse dentro de la raíz LFS. Fue necesario corregir el enlace
del cargador dinámico en `lib64` para que el ejecutable pudiera iniciarse.

Después se ejecutó:

`sudo LFS=/mnt/lfs scripts/krn-008/preparar-chroot.sh --chroot`

Resultado:

- Se verificaron los requisitos básicos.
- El script reconoció los cinco montajes que ya estaban activos.
- Se recuperó el registro persistente de los montajes.
- Se ingresó correctamente al entorno Chroot.
- Se salió mediante el comando `exit`.
- El script desmontó automáticamente `/run`, `/sys`, `/proc`,
  `/dev/pts` y `/dev`.
- La comprobación posterior con `findmnt -R /mnt/lfs` confirmó que
  únicamente permanecía montada la partición principal.
- La comprobación de `/run` confirmó que el archivo de estado había
  sido eliminado después de la limpieza.

Esta prueba confirmó el funcionamiento conjunto de `--mount`,
`--chroot`, la recuperación del estado y la limpieza automática.

## 6. Consideraciones

La comprobación de archivos y directorios básicos no garantiza por sí sola
que todos los ejecutables de la raíz LFS puedan iniciarse. También deben
estar disponibles el cargador dinámico y las bibliotecas necesarias.

Durante la prueba sobre `/mnt/lfs` se identificó y corrigió el enlace
del cargador dinámico requerido por `/usr/bin/env`.

La limpieza compara los IDs de montaje registrados con los montajes
activos para evitar desmontar puntos cuyo montaje haya cambiado.

Se verificaron los requisitos, la preparación de los montajes, el

Las pruebas confirmaron que los montajes temporales se retiran al salir
